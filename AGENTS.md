# AGENTS.md — Terra (producción terrestre de Brasil)

Static, no-framework site: `index.html` at the repo root plus the views under `pages/` (`general/`, `estadistica/`, `regresiones/`), static resources in `assets/` (`css/`, `js/`, `img/`, `fonts/`, `video/`), datasets and pipelines in `analysis/` (`data/`, `python/`, `r/`), and deliverables/references in `docs/` (`instrucciones/`, `descriptiva-brasil/`, `referencias/`, `proyecto.md`). There is no `package.json`, build, test, lint, or CI — don't invent commands. `docs/proyecto.md` is the graded Spanish outline the site must eventually cover (4.1 descriptive, 4.2 inferential, 4.3 regression/ML/time series); today the planteamiento, the map page, both statistics pages, and 4.3.1 (classical regression) are built; 4.3.2 ML and 4.3.3 time series are pending.

## Data pipeline

- Source: `analysis/data/2023_01_producao_Terra.csv` — `;`-separated, `,` decimal, `.` thousands, `utf-8-sig`, and a second subheader row. Keep those read options.
- Create the venv if missing: `python3 -m venv .venv && .venv/bin/pip install pandas numpy scipy`.
- `.venv/bin/python analysis/python/1_preprocesamiento_mapa.py analysis/data/2023_01_producao_Terra.csv` writes VAD/VAC/model JSON to `analysis/data/`. Its `analysis/data/map_data.json` and `analysis/data/estadistica_descriptiva.json` lack fields present in `analysis/data/` — don't copy them over.
- `.venv/bin/python analysis/python/2_descriptiva_inferencial.py analysis/data/2023_01_producao_Terra.csv --anual <dir>` writes straight to `analysis/data/`: `variables_estadistica.json`, `distribucion_frecuencias.json`, `indicadores_descriptivos.json`, `inferencial_ampliacion.json`, `validacion_anual.json` (downloads the 12 monthly ANP ZIPs into `<dir>` if absent; April+ files rename `Nome Poço` → `Nome Poço ANP`, Oct–Dec are Latin-1). Run it after script 1 because it reads `analysis/data/vac_oleo.json` and `analysis/data/modelo_continuo.json`.
- `.venv/bin/python analysis/python/3_regresion.py analysis/data/2023_01_producao_Terra.csv` writes `analysis/data/regresion.json` (reuses the reader from script 2).
- `python3 analysis/python/4_descriptiva_tarjetas.py` rewrites the 27 analysis cards inside `pages/estadistica/estadistica.html` from `docs/descriptiva-brasil/datos/descriptiva_brasil.json` (the 17 with report) and `analysis/data/variables_estadistica.json` (the 10 without report, field `tarjeta`; no dependencies; idempotent; the block is delimited by `<!-- TARJETAS-VARIABLES:INICIO/FIN -->`). The package itself is regenerated with `python3 docs/descriptiva-brasil/reproducibilidad/generar_descriptiva.py analysis/data/2023_01_producao_Terra.csv docs/descriptiva-brasil`.
- Repeated wells (143) are one row per Campo with the same contract: volumes are summed, production hours take the max.
- Categorical variables (Estado, Bacia, Operador, Campo, Tipo Instalação) come from the row with the most oil of each well, ties keeping the original file order, and are **not** refilled from another row. That is why Tipo Instalação has 5.096 valid / 212 missing. Campo principal counts 213 fields; the raw file has 221 (context only, never mixed).
- `analysis/data/` is the single source of truth for runtime JSON. Every `leerJSON()`/`fetch()` in `assets/js/` uses the `analysis/data/...` prefix, so don't re-add copies at the repo root or under `assets/js/`.
- `analysis/data/contexto.json` is hand-written copy (`problema`, `objetivos.general`, `objetivos.especificos`), not generated by the script. `assets/js/main.js` injects `#problema`, `#objetivo-general`, and `#objetivos-especificos` from it.

## Page wiring

- `assets/js/main.js` fetches only `analysis/data/contexto.json`. `renderContext()` fills `#problema`, `#objetivo-general`, `#objetivos-especificos`; `initReveals()` handles the scroll reveals. The old table/balance-chart renderers were removed with the data table.
- `assets/js/common.js` is the shared `leerJSON()`/`mostrarError()` helper loaded by every page (it replaced the duplicated `assets/js/commonInf.js`).
- The `<section id="planteamiento">` and the inner `<div id="planteamiento-contenido">` are intentionally different IDs. Don't collapse them.
- Motion: hero entrance, stat count-up, `IntersectionObserver` reveals (`.will-reveal`). `prefers-reduced-motion` disables all and shows final values — preserve that path.
- Responsive breakpoints are 1000, 760, 560, and 520px. No horizontal scroll.
- Fonts are self-hosted (`assets/fonts/archivo-latin.woff2`, `assets/fonts/fraunces-latin.woff2`), preloaded in `index.html`, declared at top of `assets/css/styles.css`. Don't reintroduce Google Fonts CDN.
- Accessibility: status regions, skip link, table caption/`scope`, decorative bars `aria-hidden`, `:focus-visible`, reduced-motion rule.
- Statistical wording that must stay consistent: the ANP is the administrative *source*, the file does not identify the physical instrument; oil is continuous (not an instrument-based claim); `días equivalentes completos` = `floor(max_horas/24)`, not calendar days of activity; `horas` is continuous because time is measured, and the integer resolution of the file is a limitation of the record, not of the variable; the API class is an operational split (pesado <22,3 · mediano 22,3–31,1 inclusive · ligero >31,1); the API grade is an interval scale, so CV does not apply; nominal variables get no means/SD, ordinals get a mode and a categorical median.
